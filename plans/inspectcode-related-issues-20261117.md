## Baseline: what RSRP-505529 actually claims

The issue description is the controlling source for the target symptom. It reports InspectCode `2026.3.0` / semantic version `263.0.20261106.203405` on Arch Linux x64, .NET 10 / SDK 10.0.114, `net10.0`, C# 14, nullable enabled; a single-file run with `--no-build --no-swea --no-updates --jobs=1` stalls after beginning inspection of a file containing about 1000 string literals in a `Lazy<HashSet<string>>` collection-expression factory lambda. Similar approximately-1000-element files also time out; a same-shape approximately-100-element file completes in 52.70 seconds. Earlier stacks include `ChameleonCollectionExpression.get_FirstChild`, `LambdaExpressionTypeBase.CalculateFunctionType`, `CSharpCollectionTypeUtil.GetCollectionExpressionTargetTypeInfo`, `OverloadResolutionEngine.ResolveOverloadsCore`, `CollectionExpressionCreationVerifier.Verify`, and nullable analysis. The issue explicitly says infinite loop versus expensive finite analysis, and the exact interaction among literal size, content, and overloads, are not established. ([full description API](https://youtrack.jetbrains.com/api/issues/RSRP-505529?fields=idReadable,summary,description))

This distinction matters: a report saying “Rider/InspectCode is slow” is not evidence of the same analyzer stall unless its trigger, phase, and stack/cause match.

## Practical conclusion for Reaparr

Treat RSRP-505529 as a new, currently untriaged JetBrains defect with one same-user duplicate and no independent exact match located in the searched first-party sources. The best escalation evidence is the combination of (1) the reproducible single-file/no-SWEA behavior, (2) the approximately-100-element control completing, and (3) the collection-expression/type-inference/overload-resolution/nullable-analysis stacks. RSRP-505396 and RSRP-505236 are useful for showing that 2026.3 InspectCode has other severe large/generated-code performance paths, while RIDER-145358 is useful for a potentially shared partial-type usage-collection path; none justifies changing the RSRP-505529 classification to duplicate without JetBrains establishing the same cause.
